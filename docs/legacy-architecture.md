# Academic version as domain reference

The original project at `isec/distributed-quiz` is a JavaFX desktop classroom question-and-answer system. Teachers register and sign in, create multiple-choice questions with options, correct answers and availability windows, review submissions and statistics, and export results. Students sign in, join an active question with an access code, submit one answer, and see their result after the question closes. Sessions are stored, can be resumed after reconnecting, and are revoked at logout. The original tests cover authentication, roles, question and answer rules, sessions, network transfer, replication and failover.

A directory service uses UDP registration and heartbeat messages to discover servers and elect the healthy server with the newest valid database version. Clients use UDP to find the primary, then TCP for requests and notifications. Servers exchange metadata heartbeats through multicast. Backups receive validated SQLite snapshots over TCP and can take over after primary failure. The repository is organized around client, directory, server, and shared protocol/model packages.

The future product should preserve the useful concepts: instructor and participant roles, controlled question availability, one submission per participant, delayed answer disclosure, assessment ownership, and recovery expectations. Phase 1 introduces only the broader `Assessment` aggregate as a starting point; it does not claim to implement those later rules.

JavaFX is specific to desktop deployment, while this product targets browsers and mobile viewports. Custom TCP/UDP protocols, multicast election and SQLite snapshot replication solved an academic distributed-systems exercise; they do not belong in the web foundation. A REST API and PostgreSQL provide a simpler, durable baseline. Any future real-time transport or scaling design should follow measured product needs and separate architecture decisions. No legacy source code or Git history is copied.
